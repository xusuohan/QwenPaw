## 1. 目标与范围

**目标**：消除对话请求热路径上**每次重建 LLM 客户端**的开销——缓存 `OpenAIChatModelCompat` 实例（其内部 agentscope `OpenAIChatModel` 在 `__init__` 即建 `openai.AsyncClient`，持有 httpx 连接池），让第 2 次起的同配置请求复用**热连接池**，省掉每请求一次 TLS 握手 + 客户端构建，直接降低 TTFT。

**In scope（本 spec）**：
- 在 `create_model_and_formatter`（`src/qwenpaw/agents/model_factory.py:954`）加进程内缓存，缓存内层 model 实例。
- 按 **config 指纹** keying，免失效钩子。

**Out of scope（明确不做）**：
- `load_agent_config(agent_id)` 每请求读盘（独立优化项，非 §4.1）。
- Agent 实例缓存（**C4：Agent 仍每请求重建**，本 spec 不碰）。
- wrapper / formatter 缓存（cheap，YAGNI）。
- §4.3（chats.json 缓存）、§4.5（tool result）等其他场景二项。

## 2. 生命周期事实（调查结论，设计依据）

### 2.1 请求路径（确认 C4 准确：Agent 每请求重建）

```
AgentRunner.query_handler                 # runner.py:302
  └─ NEW QwenPawAgent(...)                # runner.py:570  ← 每请求新建
       └─ __init__
            └─ create_model_and_formatter(agent_id)   # react_agent.py:161 → model_factory.py:954
                 ├─ load_agent_config(agent_id)        # 每次读盘（§4.1 外）
                 ├─ resolve (provider, model_id)       # agent-specific 分支 / global fallback 分支
                 ├─ provider.get_chat_model_instance(model_id)   # openai_provider.py:150
                 │     └─ NEW OpenAIChatModelCompat(model_name, api_key, client_kwargs, generate_kwargs)
                 │          └─ agentscope OpenAIChatModel.__init__: self.client = openai.AsyncClient(...)  ← 冷池/每次 TLS【TTFT 元凶】
                 ├─ TokenRecordingModelWrapper(provider_id, model)   # 轻量
                 ├─ RetryChatModel(wrapped, retry_config, rate_limit_config)  # 轻量
                 └─ _create_formatter_instance(inner.__class__)      # 轻量
```

agentscope 内部（`site-packages/agentscope/model/_openai_model.py:158-167`）：`self.client` 在 `__init__` 建一次，`__call__`（line 297/327）复用同一 `self.client`。→ **缓存 `OpenAIChatModelCompat` 实例 = 缓存热 httpx 池。今天每请求重建 = 每请求冷启动。**

### 2.2 三个 wrapper 均可安全共享（缓存内层 + 每请求重包 = 零行为变化）

- **`TokenRecordingModelWrapper`**（`token_usage/model_wrapper.py:16`）：`_usage_by_session` 是**类级** dict（line 19，本就进程全局）；实例字段 `_model/_provider_id/model_name` 构造后不可变。
- **`RetryChatModel`**（`retry_chat_model.py:270`）：限流器走**全局注册表** `get_rate_limiter(max_concurrent, max_qpm)`（line 353），非实例状态。→ 即便每请求新建 wrapper，限流本就是进程级；缓存内层不改变限流语义。
- **`OpenAIChatModelCompat`**（`openai_chat_model_compat.py:272`）：流式解析的 `_think_tool_calls/_text_tool_calls` 是 `_parse_openai_stream_response` 内**局部变量**（line 304-305）；实例在构造时一次性配置。→ 跨请求/跨协程共享安全，正是 httpx 连接池的设计用途。

**结论**：缓存内层 model、每请求重新包 wrapper（含 formatter），行为与今天**逐字一致**——连 C3（可接受小幅行为变更）都用不上。

### 2.3 配置变更 = 全量 Workspace 原子换

- `MultiAgentManager.reload_agent`（`multi_agent_manager.py:255`）：建全新 Workspace → `self.agents[agent_id] = new_instance`（line 375），原实例优雅停。
- 触发源：`AgentConfigWatcher`（`agent_config_watcher.py`，channels/heartbeat 变 → reload）；`schedule_agent_reload`（`app/utils.py:15`，被 `routers/providers.py:658` 等编辑端点调用）。
- provider 原地改：`update_provider`（`provider_manager.py:1113`）→ `provider.update_config(config)` 改 `api_key/base_url` 等。
- 可复用服务：3 个 service 标 `reusable=True`（`workspace.py:188/211/233`）跨 reload 存活。**本缓存不是 service、不挂 reusable**，且因指纹自愈，即便进程级常驻也不会 stale。

### 2.4 基线头号风险的破法

PROGRESS_BASELINE §6 把 §4.1 标为"最高风险"——失效钩子漏一处 = stale client = 用错 model/api_key。**破法：用 config 指纹做 key，任何配置变 → 指纹变 → 自动 miss → 新 client。stale 在结构上不可能，无需任何失效钩子。**

## 3. 设计：工厂级指纹缓存

### 3.1 放置层（已确认 = A 工厂级）

`create_model_and_formatter` 是所有 6 个 model 创建调用点（`react_agent`/`title_generator`/`skills_stream`/`proactive_responder`/`light_context_manager`/`reme_light_memory_manager`）的统一入口。在此缓存 → 单文件改动、全覆盖、blast radius 最小。

### 3.2 指纹（key）

指纹只取**决定 `OpenAIChatModelCompat` 构造的稳定输入**，且全部可从 provider 公有面 + model_id 算出，无需触碰 provider 私有构建逻辑：

```python
def _model_client_fingerprint(provider, provider_id, model_id) -> tuple:
    return (
        provider_id,
        model_id,
        provider.base_url,          # default_headers 是 base_url 的纯函数（见 2.5），由它捕获
        provider.api_key,
        json.dumps(
            provider.get_effective_generate_kwargs(model_id),
            sort_keys=True,
            default=str,
        ),
    )
```

- `base_url` 捕获 `default_headers`：`get_chat_model_instance`（`openai_provider.py:155-193`）的 headers 分支全部 `if/elif self.base_url == ...`，headers = f(base_url)。
- `generate_kwargs` 单独纳入：来自 `provider.get_effective_generate_kwargs(model_id)`，用户改某 model 的生成参数时 base_url/api_key 不变——若不纳入会 stale。该方法定义在**基类 `Provider`**（`provider.py:288`），纯内存配置合并（遍历 `self.models + self.extra_models` + deep_merge，无网络无磁盘、微秒级）→ 全部 6 类 provider（OpenAI/Gemini/Ollama/LMStudio/OpenRouter/Anthropic）统一继承，指纹天然 provider-agnostic。`update_model_config`（`provider.py:304`）就地改 `model.generate_kwargs` → 下次指纹即变 → 该变更路径也自愈。
- `api_key` 明文入 key：它本就活在 provider 对象内存里，做 dict key **不新增暴露**；纪律是**永不 log key**（日志/`cache_stats` 只报 provider_id+model_id+命中与否）。

### 3.3 缓存对象

仅内层 `ChatModelBase`（`OpenAIChatModelCompat` 及其它 provider 的对应实例）。**不缓存** wrapper、不缓存 formatter——它们每请求新建（cheap，且保语义）。

### 3.4 两分支统一走缓存

当前工厂有 agent-specific 分支（`model_factory.py:1007-1017`）与 global fallback 分支（`1018-1030`）。抽 helper `_get_cached_inner_model(provider, provider_id, model_id)`，两分支都走它：

- agent-specific：`provider = manager.get_provider(model_slot.provider_id)` → `_get_cached_inner_model(provider, model_slot.provider_id, model_slot.model)`。
- fallback：不再调 `ProviderManager.get_active_chat_model()`（其内自建、绕过缓存），改为 `global_model = manager.get_active_model()` → `provider = manager.get_provider(global_model.provider_id)` → `_get_cached_inner_model(provider, global_model.provider_id, global_model.model)`。
- `get_active_chat_model`（`provider_manager.py:2022`）经 grep 仅被工厂这一处调用，重构安全（保留其定义不删，避免破坏外部 import 面）。

### 3.5 开关 / 容量 / 线程安全

- **开关**：env `QWENPAW_PERF_MODEL_CLIENT_CACHE`，**默认开**，`0/false/no` 关（沿用 `import_prefetch` 的 `QWENPAW_PERF_*` 模式）。关时 `_get_cached_inner_model` 直接 `return provider.get_chat_model_instance(model_id)`，完全不碰 dict = 与今天逐字相同（逃生通道）。
- **容量**：`_MODEL_CLIENT_CACHE_CAP = 64`（远超实际：≤20 provider × 几个 model × 偶发换 key）。达 cap 时丢最旧（`dict` 保序，`next(iter(...))` pop）。
- **线程安全**：`create_model_and_formatter` 是同步函数；`threading.Lock` 包 dict 读写（C2 单实例进程内并发，GIL + 可能的 worker 线程）。

## 4. 公共 API（新增，全在 `model_factory.py`）

```python
_MODEL_CLIENT_CACHE: dict[tuple, ChatModelBase] = {}
_MODEL_CLIENT_CACHE_LOCK = threading.Lock()
_MODEL_CLIENT_CACHE_CAP = 64

def _model_client_cache_enabled() -> bool            # 解析 env，默认 True
def _model_client_fingerprint(provider, provider_id, model_id) -> tuple
def _get_cached_inner_model(provider, provider_id, model_id) -> ChatModelBase
def clear_model_client_cache() -> None               # 测试 + 紧急重置
def model_client_cache_stats() -> dict               # {"size","hits","misses"}；绝不吐 key 材料
```

`create_model_and_formatter` 内：把两分支的 `provider.get_chat_model_instance(...)` / `ProviderManager.get_active_chat_model()` 替换为 `_get_cached_inner_model(...)`；wrapper 与 formatter 段不变。

## 5. 数据流（after）

```
create_model_and_formatter(agent_id)
  load_agent_config(agent_id)                        # 读盘（保留，§4.1 外）
  resolve (provider, provider_id, model_id)          # 两分支统一
  inner = _get_cached_inner_model(provider, provider_id, model_id)
      if not _model_client_cache_enabled(): return provider.get_chat_model_instance(model_id)  # 逃生
      fp = _model_client_fingerprint(provider, provider_id, model_id)
      lock:
          if fp in cache: hits++; return cache[fp]    # 命中：复用热池，0 构建 / 0 TLS
      build = provider.get_chat_model_instance(model_id)   # miss 才付构建费
      lock:
          cache[fp] = build; 若超 cap 丢最旧; misses++
      return build
  wrapped = TokenRecordingModelWrapper(provider_id, inner)   # 每请求新包
  wrapped = RetryChatModel(wrapped, retry_config, rate_limit_config)
  formatter = _create_formatter_instance(inner.__class__)   # 每请求新建
  return wrapped, formatter
```

## 6. 错误处理 / 边界

| 情形 | 行为 |
|---|---|
| `get_chat_model_instance` 构建抛错 | 不写缓存，异常正常上抛（与现状一致） |
| 开关关 | 直通 `get_chat_model_instance`，不碰 dict = 与今天一致 |
| 改 api_key/base_url/generate_kwargs | 指纹变 → miss → 新 client；旧 entry 滞留至 cap 驱逐（内存有界） |
| 换 provider / 注册新 provider | 新 provider 实例自带空缓存面（cache 是模块级 dict，按指纹隔离，不会串） |
| 跨 agent 同配置 | 命中**同一**实例 = 共享热池（收益，非 bug） |
| `reload_agent` 全量换 Workspace | 模块级缓存常驻；但因指纹自愈，新 Workspace 首请求按当前配置算指纹 → 正确命中或 miss，**不会 stale** |

## 8. 残余风险与取舍

1. **agentscope `AsyncClient` 跨大量并发流共享**：是其设计用途（连接池），但极端并发下若有未知 bug → kill-switch `QWENPAW_PERF_MODEL_CLIENT_CACHE=0` 一键关。默认开（指纹已让头号风险归零，且要 ON 才有 TTFT 价值）。
2. **fallback 分支重构**：把 `get_active_chat_model()` 调用改为 resolve + `_get_cached_inner_model`。已 grep 确认仅工厂一处调用，安全。
3. **指纹完整性（已核实）**：`get_effective_generate_kwargs` 在基类 `Provider`（`provider.py:288`）、纯内存配置合并、6 类 provider 统一继承 → 指纹 provider-agnostic 且 cheap，每请求算一次远廉于构建 httpx 客户端。`update_model_config` 改 per-model 参数也经指纹自愈。实施时仅需保证 `json.dumps(..., sort_keys=True, default=str)` 对 deep_merge 结果确定可哈希。
4. **`load_agent_config` 读盘仍在**：每请求一次读盘未被本 spec 消除（独立项）。指纹检查在 `load_agent_config` 之后，故读盘开销不因缓存减少——§4.1 收益纯粹来自省掉 httpx 客户端构建 + TLS。

## 9. C1–C5 合规

| 约束 | 合规 |
|---|---|
| C1 USB/exFAT | 缓存纯内存，无磁盘 IO；exFAT 无关 |
| C2 单实例进程内并发 | `threading.Lock` 进程内串行化 dict 读写；无跨进程 |
| C3 小幅行为变更可接受 | 实际**零行为变更**（内层共享是 httpx 设计用途，wrapper 每请求重包） |
| C4 请求路径深度中等 | **只缓存 model client；Agent 实例仍每请求重建**（本 spec 不碰 runner.py:570） |
| C5 不碰宿主磁盘 | 纯内存，无文件操作 |
